## 1. 背景与目标

### 1.1 项目背景

医药监管上层通用 Agent 项目，当前重点场景包括：标书审查、合同预审、风险预警。项目需要建设通用知识库，所有场景共享，为 AI 回答提供可溯源的知识增强能力。

**现状问题**：
- RAG 实现架构混乱，AgentSceneService 直接持有并调用 RAG 基础设施（越层调用）
- RAG 检索时 scene 参数传 null，导致全库裸搜，不按业务场景过滤
- 标书审查等场景完全没有 RAG 知识增强
- EvidenceItem 和 RagCitation 模型重复定义

### 1.2 问题陈述

我们发现当前 RAG 存在以下核心问题：
1. **架构混乱**：场景层直接操作 RAG 基础设施，违反分层架构
2. **检索不准确**：参数丢失导致返回无关知识片段
3. **功能缺失**：关键业务场景（标书审查）缺少知识增强
4. **模型冗余**：多个相似的数据模型增加复杂度

### 1.3 目标

| 目标类型 | 描述 |
|----------|------|
| 核心目标 | 建设通用知识库，所有场景按需调用，实现知识增强 |
| 架构目标 | 清晰的 RAG 调用层次，场景 Workflow 按需调用 RAG |
| 管理目标 | 提供知识库管理页面，支持 MD/PDF 文件导入 |

### 1.4 成功标准

- 知识库管理页面可正常导入 MD 文件
- 标书审查场景可按需检索相关法规知识
- RAG 检索结果准确关联当前业务场景
- 回答可附带知识引用（citations）

## 2. 用户画像

### 2.1 主要用户

| 用户角色 | 职责 | 使用场景 |
|----------|------|----------|
| 机构管理员 | 维护知识库，上传 MD/PDF 文件 | 知识库配置 |
| 审查人员 | 使用标书审查、合同预审等功能 | 业务审查 |

### 2.2 用户痛点

1. **知识分散**：药品名称、法规条文分散在各处，AI 回答缺乏统一知识源
2. **引用缺失**：AI 回答无法提供来源依据，难以验证准确性
3. **检索不准**：现有 RAG 检索返回无关内容，影响判断

## 3. 功能需求

### 3.1 知识库管理

| 需求编号 | 功能 | 描述 | 优先级 |
|----------|------|------|--------|
| KG-001 | 文件导入 | 支持上传 MD 格式文件，解析入库 | P0 |
| KG-002 | 文件列表 | 展示已导入文件列表，支持删除 | P1 |
| KG-003 | 格式转换支持 | 后期支持 PDF 格式导入 | P2 |

**知识库内容类型**：

| 知识类型 | 示例 |
|----------|------|
| 药品名称 | 常用药品名称库、药品监管目录 |
| 法规制度 | 《招标投标法》《政府采购法》《药品管理法》 |
| 审查标准 | 标书审查标准、合同审核要点 |
| 历史案例 | 监管处罚案例、风险预警案例 |

### 3.2 RAG 检索服务

| 需求编号 | 功能 | 描述 | 优先级 |
|----------|------|------|--------|
| RG-001 | 通用检索 | 按 orgId + scene 过滤的向量检索 | P0 |
| RG-002 | 混合检索 | 向量检索 + BM25 关键词检索融合 | P1 |
| RG-003 | 重排优化 | relevance + diversity 重排 | P1 |
| RG-004 | 引用返回 | 返回 answer + citations | P0 |

**检索参数**：

| 参数 | 说明 | 必填 |
|------|------|------|
| query | 用户问题 | 是 |
| orgId | 机构 ID（硬过滤） | 是 |
| scene | 业务场景（可选过滤） | 否 |
| subScene | 子场景（可选过滤） | 否 |
| docType | 文档类型（可选过滤） | 否 |
| topK | 返回数量（默认 5） | 否 |

**检索结果**：

| 字段 | 说明 |
|------|------|
| answer | 基于证据的回答（可选） |
| citations | 引用列表 |
| decision | 命中决策（HIT/NO_HIT/NEED_HUMAN_REVIEW） |
| reason | 命中原因 |

### 3.3 场景 Workflow 集成

| 需求编号 | 场景 | RAG 增强内容 | 优先级 |
|----------|------|-------------|--------|
| WG-001 | 标书审查 | 关联《招标投标法》《政府采购法》、行业监管要求 | P0 |
| WG-002 | 合同预审 | 关联《合同法》条款、历史合同纠纷案例 | P1 |
| WG-003 | 风险预警 | 关联监管处罚案例、风险指标定义 | P1 |

**集成方式**：场景 Workflow 内部按需调用 RAG，不是 Orchestrator 主动检索后传递给 Workflow。

## 4. 架构设计

### 4.1 正确架构

```
┌─────────────────────────────────────────────────────────────────┐
│                        AgentChatService                         │
│                     （统一上下文、路由分发）                      │
└─────────────────────────────────────────────────────────────────┘
                                │
                                ▼
┌─────────────────────────────────────────────────────────────────┐
│                    Scene Orchestrator                            │
│              （场景编排器，如 TenderReviewOrchestrator）          │
│                                                                  │
│  ┌─────────────┐    ┌─────────────┐    ┌─────────────┐          │
│  │ Tool 注册   │    │ 结果接收    │    │ LLM 整理   │          │
│  └─────────────┘    └─────────────┘    └─────────────┘          │
└─────────────────────────────────────────────────────────────────┘
                    │                           │
                    ▼                           ▼
┌─────────────────────────┐    ┌─────────────────────────────────┐
│   KnowledgeRetrievalTool │    │      TenderReviewWorkflow       │
│   （RAG 统一入口）        │    │  （场景业务逻辑，内部按需调用）   │
└─────────────────────────┘    └─────────────────────────────────┘
                    │                           │
                    ▼                           ▼
┌─────────────────────────────────────────────────────────────────┐
│                         RagService                              │
│                    （RAG 核心检索服务）                           │
│                                                                  │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐        │
│  │ Embedding│  │  向量库   │  │  混合检索 │  │   重排   │        │
│  │ Service  │  │ (PGVector)│  │  Service │  │ Service  │        │
│  └──────────┘  └──────────┘  └──────────┘  └──────────┘        │
└─────────────────────────────────────────────────────────────────┘
                                │
                                ▼
┌─────────────────────────────────────────────────────────────────┐
│                      知识库管理页面                              │
│                  （文件导入、列表管理）                           │
└─────────────────────────────────────────────────────────────────┘
```

### 4.2 关键原则

| 原则 | 说明 |
|------|------|
| 通用知识库定位 | RAG 是通用基础设施，所有场景共享 |
| 场景按需调用 | 场景 Workflow 内部按需调用 RAG，不是被动接收 |
| 参数完整传递 | 检索时必须传递 orgId + scene 等过滤参数 |
| 分层清晰 | 场景层不直接操作 RAG 基础设施 |

### 4.3 当前架构问题与修复

| 问题 | 当前状态 | 修复方案 |
|------|----------|----------|
| 越层调用 | AgentSceneService 直接持有 KnowledgeRetrievalTool | 移除场景层对 RAG 基础设施的直接依赖 |
| 参数丢失 | scene 参数传 null | Workflow 调用时正确传递 scene |
| 功能缺失 | TenderReviewWorkflow 无 RAG 调用 | 在 Workflow 内部按需检索法规知识 |
| 模型冗余 | EvidenceItem 和 RagCitation 重复 | 统一数据模型 |

### 5.2 文件导入流程

```
用户上传文件
    │
    ▼
前端校验（格式、大小）
    │
    ▼
上传到 COS 存储
    │
    ▼
调用后端接口解析入库
    │
    ▼
文本提取 → chunk 切分 → embedding → 向量库存储
    │
    ▼
返回导入结果
```

## 6. 接口设计

### 6.1 文件导入

| 项目 | 说明 |
|------|------|
| 接口路径 | `POST /api/knowledge/upload` |
| 请求格式 | multipart/form-data |
| 请求参数 | file（文件）、orgId（机构ID）、docType（文档类型） |

**响应示例**：

```json
{
  "code": 200,
  "message": "导入成功",
  "data": {
    "fileId": "file_123456",
    "fileName": "招标投标法.md",
    "chunkCount": 50,
    "status": "SUCCESS"
  }
}
```

### 6.2 知识检索

| 项目 | 说明 |
|------|------|
| 接口路径 | `POST /api/knowledge/retrieve` |
| 请求格式 | application/json |

**请求示例**：

```json
{
  "query": "什么是围标行为？",
  "orgId": "org_001",
  "scene": "tender_review",
  "topK": 5
}
```

**响应示例**：

```json
{
  "code": 200,
  "data": {
    "decision": "HIT",
    "reason": "找到相关法规条文",
    "citations": [
      {
        "chunkId": "chunk_001",
        "sourceTitle": "招标投标法",
        "snippet": "围标是指投标人之间相互串通...",
        "score": 0.95
      }
    ]
  }
}
```

## 7. 验收标准

### 7.1 知识库管理

| 验收项 | 验收条件 |
|--------|----------|
| 文件上传 | MD 文件可正常上传并入库 |
| 文件列表 | 展示所有已导入文件 |
| 文件删除 | 可删除文件并清理向量库记录 |

### 7.2 RAG 检索

| 验收项 | 验收条件 |
|--------|----------|
| 场景过滤 | 传入 scene 参数后，只返回该场景相关知识 |
| orgId 过滤 | 只返回该机构导入的知识 |
| 引用准确 | 返回的 citation 内容与问题相关 |

### 7.3 场景集成

| 验收项 | 验收条件 |
|--------|----------|
| 标书审查增强 | 审查时可检索相关法规作为判断依据 |
| 回答引用 | 回答可附带知识来源引用 |

## 10. 风险点

| 风险编号 | 风险描述 | 缓解措施 |
|----------|----------|----------|
| R01 | PDF 解析质量不佳导致知识入库不完整 | 前期先做 MD 格式，PDF 解析后期迭代 |
| R02 | 向量检索召回不准确 | 引入混合检索 + 重排优化 |
| R03 | 场景 Workflow 过度依赖 RAG | 明确 RAG 是补充而非依赖，Workflow 自身逻辑优先 |
