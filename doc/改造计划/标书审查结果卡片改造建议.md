# 标书审查结果卡片改造建议

## 1. 文档目的

本文档用于梳理当前“标书审查结果卡片”在信息呈现上的问题，并给出一套更贴近业务用户认知的改造建议。

本次改造的重点不是视觉细节，而是：

- 结果卡片到底应该给谁看
- 什么信息该默认展示
- 什么信息应该下沉到详情层
- 如何让卡片更像“业务结果卡”，而不是“系统执行回显”

## 2. 当前问题判断

从当前卡片内容来看，主要存在以下问题：

### 2.1 结果卡片偏“系统视角”，不够“用户视角”

当前卡片展示了大量偏系统内部的信息，例如：

- 执行步骤
- 结构化加载
- 风险融合
- 证据组装
- 报告生成

这些内容对研发、测试、演示调试可能有帮助，但对业务用户来说优先级不高。

业务用户真正关心的是：

- 结论是什么
- 风险高不高
- 为什么这么判断
- 我下一步应该做什么

### 2.2 “执行步骤”展示优先级过高

当前卡片中，“执行步骤”被放在摘要之后，并且视觉权重较高。

这会产生两个问题：

- 用户注意力被系统流程吸走
- 结果卡片变得像“内部处理面板”

结论：

- `执行步骤` 不适合出现在默认结果卡主区域
- 更适合放入“查看处理过程”二级抽屉或技术详情面板

### 2.3 指标字段不够产品化

当前卡片中有一些字段不够贴近业务语言，例如：

- `参考分值`
- `有效风险项`

这些词更像内部数据字段，而不是自然的业务表达。

#### 建议

- `参考分值` 改为 `风险评分`，或者默认不展示
- `有效风险项` 改为 `风险命中`

### 2.4 低风险场景下“关键证据”表达不自然

当结果是低风险时，当前卡片仍然使用“关键证据”这一标题。

但在低风险场景下，用户实际想看到的是：

- 未发现哪些高风险信号
- 为什么判断风险较低
- 是否仍建议人工抽样复核

因此，低风险时更适合使用：

- `审查说明`
- `扫描结论`
- `复核建议`

而不是统一叫“关键证据”。

### 2.5 摘要信息存在重复

当前页面上方消息气泡已经展示了一遍结论，结果卡中又重复一次相同内容。

这会造成：

- 信息密度不高
- 卡片空间被重复内容占用
- 用户看不到更多真正新增的信息

## 3. 结果卡片的正确定位

建议将“标书审查结果卡片”定位为：

**给业务用户看的一级结果摘要卡**

它的职责应该是：

- 快速告诉用户当前结论
- 快速提示风险等级
- 快速说明为什么
- 快速指引下一步动作

它不应该承担：

- 展示全部系统执行过程
- 展示全部内部步骤
- 展示所有技术术语
- 替代完整报告页

## 4. 推荐的信息架构

建议将结果卡片拆成两层：

### 4.1 默认展示层

默认层只展示业务用户最关心的信息。

建议保留：

- 风险等级
- 一句话结论
- 核心指标 2-3 个
- 审查说明
- 建议动作
- 查看详情 / 查看完整报告按钮

### 4.2 二级展开层

二级层展示更深的系统或技术信息。

建议下沉：

- 执行步骤
- 处理过程
- traceId
- caseId
- 规则技术名
- 中间处理状态

## 5. 建议的默认卡片结构

建议结果卡片采用如下结构：

### A. 顶部结果区

展示：

- 风险等级标签
- 场景名称
- 一句话结论

示例：

```text
低风险
已完成 2 份标书比对，当前未发现有效高风险命中
```

### B. 核心指标区

建议只保留 2-3 个最有解释力的指标。

推荐字段：

- 对比文件数
- 风险命中数
- 风险评分（可选）

对于业务用户，建议避免堆太多指标。

### C. 审查说明区

这一部分是卡片的重点。

建议展示：

- 未发现哪些高风险信号
- 当前判断依据是什么
- 是否建议人工复核

低风险示例：

- 未检测到联系人复用、团队重叠、报价异常等高风险信号
- 当前样本在规则维度偏差较小
- 如为重点项目，建议抽样人工复核

高风险示例：

- 检测到联系人与团队成员存在交叉复用
- 检测到报价梯度异常
- 建议优先进入人工复核流程

### D. 操作区

建议只保留清晰的下一步动作：

- 查看完整报告
- 查看详情
- 查看证据

如果一定要保留“查看处理过程”，建议作为次级操作，不要与主按钮同级抢主视觉。

## 6. 当前展示字段的取舍建议

| 当前字段 | 是否建议默认展示 | 建议 |
|---|---|---|
| 风险等级 | 是 | 保留 |
| 场景名称 | 是 | 保留 |
| caseId / traceId | 否 | 下沉到详情 |
| 综合风险 | 是 | 可保留，但避免重复 |
| 参考分值 | 视情况 | 建议改名为风险评分或隐藏 |
| 比对文件 | 是 | 保留 |
| 有效风险项 | 是 | 改名为风险命中 |
| 结果摘要 | 是 | 保留，但与气泡内容避免重复 |
| 执行步骤 | 否 | 下沉到处理过程面板 |
| 关键证据 | 视风险等级而定 | 低风险改为审查说明，高风险保留证据表达 |

## 7. 不同风险等级下的展示策略

建议不要让高风险、中风险、低风险三种情况完全使用同一套文案结构。

### 7.1 低风险

重点表达：

- 未发现明显高风险信号
- 当前样本规则偏差较小
- 是否需要抽样复核

应弱化：

- 证据对抗感
- 执行步骤
- 技术内部流程

### 7.2 中风险

重点表达：

- 有一定异常点，需要复核
- 风险不确定但值得关注
- 建议核查哪些方向

### 7.3 高风险

重点表达：

- 命中了哪些关键风险信号
- 高风险依据是什么
- 为什么值得立即复核
- 下一步建议动作

高风险时可以更强调：

- 证据链
- 命中规则
- 复核建议

## 8. 对“执行步骤”的具体建议

### 当前问题

当前执行步骤包括：

- 场景路由
- 结构化加载
- 规则命中分析
- 误报豁免
- 风险融合
- 证据组装
- 报告生成

这些信息本质上是系统内部流水线。

### 建议做法

#### 默认卡片中

不展示执行步骤。

#### 详情页或二级抽屉中

可以展示为：

- 处理过程
- 系统执行记录
- 分析过程

适用场景：

- 用户主动点击“查看处理过程”
- 演示模式
- 开发/测试定位问题

### 为什么要下沉

因为这类信息：

- 对业务结论没有直接帮助
- 会干扰结果主信息的传达
- 让卡片更像“后台处理过程展示”

## 9. 推荐的改造方向

建议按以下顺序改造：

### 第一阶段：先做信息收敛

- 去掉默认展示的执行步骤
- 下沉 traceId / caseId
- 精简指标区
- 统一文案口径

### 第二阶段：强化“结果 + 原因 + 建议动作”

- 增强审查说明
- 增强建议动作
- 明确不同风险等级下的内容模板

### 第三阶段：补充二级详情

- 查看处理过程
- 查看证据明细
- 查看完整报告

## 10. 推荐的最终展示模型

建议将结果卡片理解为三问模型：

### 第一问：结果是什么？

- 高风险 / 中风险 / 低风险
- 当前是否发现有效风险命中

### 第二问：为什么？

- 命中了哪些风险信号
- 或未发现哪些关键高风险信号

### 第三问：下一步做什么？

- 查看完整报告
- 进入人工复核
- 抽样复核 / 归档

只要这三问答清楚，这张卡片就能真正服务业务用户。

## 11. 结论

当前“标书审查结果卡片”的问题，本质上不是内容不够，而是：

- 给用户看了太多系统内部信息
- 给用户真正关心的业务结论和下一步动作还不够聚焦

尤其是：

- `执行步骤` 不适合作为默认主信息展示
- 它更适合下沉到详情层或处理过程层

建议后续将结果卡片重新组织为：

- 风险等级
- 一句话结论
- 核心指标
- 审查说明
- 建议动作

这样会更符合“标书审查 Agent”作为业务产品的定位。
