# 原型意图版前端功能开发方案

## 文档目标

本方案用于把 `原型.vue` 中体现出来的页面意图，整理成一份可交付给前端开发者执行的功能方案。

本方案只描述：

- 页面应该具备哪些功能
- 信息结构应该如何组织
- 用户操作链路应该如何设计
- 哪些能力进入 MVP，哪些能力暂缓

本方案不描述：

- React 写法
- 具体代码实现方式
- 组件内部实现细节
- 视觉像素级还原要求

## 技术前提

本次前端实现统一基于以下技术栈：

- `Vue 3`
- `tdesign-vue-next`
- `@tdesign-vue-next/chat`

要求：

1. 页面基础容器、按钮、输入框、抽屉、标签、列表、布局等能力使用 `tdesign-vue-next`
2. 对话区域基础能力使用 `@tdesign-vue-next/chat`
3. 不再使用原型中的 React 组件和 React 交互方式
4. 不引入第二套聊天 UI 框架

## 一、原型的核心产品意图

从原型来看，这个页面不是一个“普通聊天窗口”，而是一个：

**面向医药监管场景的 Agent 审查工作台**

它承载的核心意图有 4 个：

1. 让用户快速进入某个审查任务
2. 让用户在同一个界面里持续查看历史会话和当前分析过程
3. 让系统对不同场景进行统一承接，例如标书审查、合同预审、合规预警
4. 让结果不只是一段文字，而是结构化审查结论

所以本页面的目标不是做“聊天感”，而是做“工作台感”。

## 二、页面功能定位

首页应当被定义为：

**Agent 工作台首页**

它既是默认进入页，也是主操作页。

首页要同时承担：

- 新建审查会话
- 切换历史审查会话
- 输入问题
- 上传文件
- 查看审查回复
- 查看结构化结果

## 三、首页功能结构

首页应包含 3 个核心功能区：

### 1. 左侧功能区

用于承接“导航 + 历史会话”。

必须具备：

- 品牌区
- 新建会话入口
- 一级导航入口
- 历史会话列表
- 会话分组展示
- 会话搜索
- 系统设置入口

说明：

- 一级导航本期可以先保留静态入口，不要求全部跳转完成
- 历史会话必须是首页的一部分，不能放到二级页面

### 2. 中间主工作区

用于承接“欢迎态 + 对话流 + 结果卡片 + 输入交互”。

必须具备：

- 默认欢迎态
- 快捷操作入口
- 当前会话消息流
- 用户消息展示
- 智能体消息展示
- 结果卡片展示
- 输入框
- 上传入口

说明：

- 中间区域是页面主角
- 欢迎态不是空白占位，而是一个引导用户开始任务的入口区

### 3. 顶部状态区

用于承接“当前上下文 + 轻量任务状态”。

必须具备：

- 当前页面标题
- 当前会话标题
- 活跃任务状态提示
- 当前用户或系统标识

说明：

- 顶部状态区只做轻量信息承接
- 不做复杂工具栏堆叠

## 四、欢迎态功能要求

当用户还没有选中会话，或当前会话还没有消息时，首页应展示欢迎态。

欢迎态必须具备：

### 1. 系统身份表达

要让用户一进入页面就知道：

- 这是一个监管审查智能体
- 它不是普通客服机器人
- 它能处理多个监管分析场景

### 2. 快捷任务入口

欢迎态中应提供 3 个快捷入口：

- 标书审查
- 合同预审
- 合规预警

点击后效果：

- 自动把对应提示词填入并触发发送
或
- 自动创建一条会话并进入对应场景的初始提问

### 3. 操作引导

欢迎态要告诉用户两件事：

- 可以直接输入问题
- 也可以上传文件发起审查

## 五、会话区功能要求

会话区是首页的长期主功能。

必须具备以下能力：

### 1. 会话展示

左侧展示历史会话时，要支持：

- 按时间分组
- 标题展示
- 场景标签
- 更新时间展示
- 当前会话高亮

### 2. 会话操作

本期支持：

- 新建会话
- 选择会话
- 删除会话

本期不强制要求：

- 重命名会话
- 收藏会话
- 批量管理

### 3. 会话切换逻辑

切换历史会话后，主区域必须立即展示对应历史消息与结果。

要求：

- 不能只切标题不切内容
- 不能造成消息错位

## 六、消息流功能要求

消息流是首页的核心交互结构。

### 1. 用户消息

用户消息需要支持：

- 纯文本展示
- 附件信息展示

### 2. 智能体消息

智能体消息需要至少支持 3 种类型：

- 普通文本回复
- 澄清型回复
- 结果卡片型回复

### 3. 状态消息

系统需要支持基础状态提示：

- 正在思考
- 正在上传
- 请求失败

### 4. 自动滚动

新消息出现后，消息区应自动滚动到底部。

## 七、输入区功能要求

输入区是用户发起任务的主要入口。

必须具备：

- 文本输入
- 发送按钮
- 上传入口

说明：

- 上传入口可以做成按钮或图标
- 发送和上传必须在一个连续操作区中完成

本期不要求：

- 多行复杂编辑器
- slash 命令
- 智能提示补全

## 八、上传功能要求

上传功能是本项目的关键业务入口，尤其对标书审查场景。

本期必须具备：

- 选择文件
- 展示已选文件列表
- 删除待上传文件
- 填写附加说明
- 提交上传

交互要求：

- 上传动作应当发生在当前会话上下文中
- 上传成功后，结果应进入当前会话消息流

本期不要求：

- 分片上传
- 拖拽排序
- 批量进度条矩阵
- 上传历史管理中心

## 九、结果展示功能要求

原型的一个核心意图是：

**结果不能只是一段聊天文本，而要具备结构化表达。**

因此首页必须支持结果卡片。

### 1. 结果卡片

结果卡片至少展示：

- 风险等级
- 摘要
- 分数
- 查看详情入口

### 2. 结果详情

点击结果卡片后，应打开详情区域，建议使用 `tdesign-vue-next` 的抽屉。

详情中应支持展示：

- 风险等级
- 评分
- 审查摘要
- 审查步骤
- 证据列表
- 报告内容

### 3. 展示原则

本期只要求“信息完整可读”，不要求复杂的图谱化展示。

## 十、顶部状态区功能要求

顶部状态区本期只做轻量状态承接。

必须具备：

- 当前页面名称
- 当前会话标题
- 活跃任务数量或状态提示
- 用户标识

说明：

- 原型里有“任务中心弹层”意图
- 但在 MVP 阶段，可以先只保留一个“活跃任务状态提示”
- 复杂任务面板可以留到后续版本

## 十一、一级导航功能要求

原型中表现出 3 类一级空间：

- 智能体工作台
- 全局任务看板
- 合规知识库

本期要求如下：

### 1. 智能体工作台

必须完成，作为首页主页面。

### 2. 全局任务看板

本期可以只保留导航入口，不强制完成完整页面。

### 3. 合规知识库

本期可以只保留导航入口，不强制完成完整页面。

说明：

- 当前阶段首页只需要把信息架构留出来
- 不要求一次性把所有一级页面开发完

## 十二、MVP 范围定义

为了防止过度设计，本期首页只做以下功能闭环：

1. 用户进入首页
2. 用户看到欢迎态和快捷入口
3. 用户可以创建或切换会话
4. 用户可以输入文本或上传文件
5. 系统返回文本回复或结构化结果
6. 用户可以打开结果详情

## 十三、本期明确不做

以下能力不进入本期首页开发：

- 多 Agent 并行执行面板
- Trace 图谱展示
- 工作流执行节点可视化
- 复杂任务中心弹层
- 高级筛选器
- 细粒度权限切换
- 深色模式
- 国际化
- 高保真动画系统
- 高复杂度移动端适配

## 十四、对开发者的实施要求

开发者在实现时应遵守以下约束：

### 1. 只用一套 UI 基础

统一使用：

- `tdesign-vue-next`
- `@tdesign-vue-next/chat`

### 2. 不要照搬 React 结构

`原型.vue` 只用于提取产品意图，不作为实现模板。

### 3. 不要把首页做成纯聊天页

首页必须保留“工作台”感，包括：

- 历史会话
- 快捷入口
- 结构化结果
- 顶部状态信息

### 4. 不要为了未来能力过度抽象

本期重点是页面可用，不是构建前端平台框架。

## 十五、最终交付标准

只要首页能达到以下状态，就算满足本方案目标：

1. 页面结构与原型意图一致
2. 左侧有会话和导航，中间有工作区，顶部有状态区
3. 欢迎态可引导用户开始任务
4. 对话、上传、结果卡片三类核心链路可承接
5. 页面基于 `Vue 3 + tdesign-vue-next + @tdesign-vue-next/chat` 实现

## 结论

这个原型真正想表达的，不是一个“更好看的聊天框”，而是一套：

**面向监管审查业务的 Agent 工作台首页。**

因此前端开发时必须优先确保：

- 工作台结构完整
- 任务入口明确
- 会话连续性清晰
- 结果表达结构化

只要守住这四点，就没有偏离原型的核心意图。
