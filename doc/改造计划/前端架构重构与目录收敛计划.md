# 前端架构重构与目录收敛计划

## 1. 改造目标

前端这次改造的目标，不是把目录弄得更“规范”，而是把项目整理成一套：

1. 简单
2. 好找
3. 好维护
4. 后续扩展不别扭

当前前端主要问题是：

1. `api`、`services`、`shared/api` 三套接口调用方式并存
2. `components`、`feature`、`views` 的边界不够清晰
3. `utils`、`shared/util`、`stores` 比较分散
4. 同一种东西经常有两种放法，后面会越改越乱

所以这次前端改造的目标就是：

**只保留一套简单、稳定、容易理解的目录表达。**

---

## 2. 命名原则

为了适配中文团队，这次前端目录也优先用短词和常用词。

### 2.1 顶层目录尽量简单

推荐保留这些目录：

- `app`
- `pages`
- `module`
- `component`
- `store`
- `api`
- `utils`
- `style`
- `assets`

说明：

- `pages` 比 `views` 更直观
- `module` 比 `feature` 更好懂
- `component` 只保留一套公共组件目录
- `api` 作为唯一接口基础层
- `style` 统一样式目录

### 2.2 模块名尽量贴近业务

推荐统一为：

- `agent`
- `tender`
- `task_board`
- `workspace`
- `setting`

如果后面知识库单独做得更重，可以再补一个：

- `knowledge`

### 2.3 模块内部结构尽量统一

每个模块优先只保留：

- `component`
- `api`
- `store`

这样阅读体验会统一很多。

---

## 3. 最终推荐目录总览

```text
drug-agent-web/src/                        # 前端源码根目录
├── app/                                  # 应用入口和全局装配
├── pages/                                # 路由级页面
├── module/                               # 业务模块目录
├── component/                            # 全局公共组件
├── store/                                # 全局共享状态
├── api/                                  # 全局请求基础层
├── utils/                                # 通用工具
├── style/                                # 全局样式
└── assets/                               # 静态资源
```

这套结构的核心思路是：

- 页面放 `pages`
- 业务模块放 `module`
- 真正公共的东西单独放
- 同一种东西只保留一套目录表达

---

## 4. 最终推荐目录和文件说明

### 4.1 `app/`

放前端应用入口和全局装配。

```text
app/
├── App.vue                               # 应用根组件
├── main.js                               # 应用启动入口
└── router/
    └── index.js                          # 路由配置
```

说明：

- `App.vue` 作为应用壳
- `main.js` 挂载 Vue 应用
- `router/index.js` 管理路由表

这里不要堆业务逻辑。

---

### 4.2 `pages/`

放页面级组件，也就是路由直接对应的页面。

```text
pages/
├── WorkspacePage.vue                     # 工作台首页
├── TaskBoardPage.vue                     # 任务看板页
├── TaskDetailPage.vue                    # 任务详情页
├── KnowledgePage.vue                     # 知识库页
├── SettingsPage.vue                      # 设置页
├── HelpPage.vue                          # 帮助中心页
└── AuditLogPage.vue                      # 审计日志页
```

说明：

- 页面负责拼装模块和布局
- 页面里可以有少量页面级逻辑
- 不要把大量通用组件直接堆在页面里

---

### 4.3 `module/`

这是前端最核心的目录，按业务模块聚合代码。

```text
module/
├── agent/                                # Agent 对话模块
│   ├── component/                        # Agent 模块专属组件
│   │   ├── MessageBubble.vue             # 消息气泡
│   │   ├── AgentResultPanel.vue          # Agent 结果面板
│   │   ├── ExecutionLog.vue              # 执行日志面板
│   │   └── chat/
│   │       ├── ChatMessage.vue           # 聊天消息组件
│   │       ├── SessionList.vue           # 会话列表
│   │       └── SessionSidebar.vue        # 会话侧栏
│   ├── api/
│   │   ├── agent.js                      # Agent 接口
│   │   └── gemini.js                     # 如果保留前端直连模型能力，可放这里
│   └── store/
│       ├── chatStore.js                  # 聊天状态
│       └── session.js                    # 会话状态
│
├── tender/                               # 标书审查模块
│   ├── component/
│   │   ├── EvidencePanel.vue             # 证据面板
│   │   └── TaskQuickView.vue             # 任务快速查看
│   ├── api/
│   │   └── tender.js                     # 标书接口
│   └── store/
│       └── task.js                       # 标书任务状态
│
├── task_board/                           # 看板模块
│   ├── component/
│   │   ├── TaskBoard.vue                 # 看板主组件
│   │   ├── TaskCard.vue                  # 看板卡片
│   │   ├── TaskDetailDrawer.vue          # 任务详情抽屉
│   │   ├── CreateTaskModal.vue           # 创建任务弹窗
│   │   ├── StatsPanel.vue                # 统计面板
│   │   ├── FilterBar.vue                 # 筛选栏
│   │   └── EmptyState.vue                # 空状态组件
│   ├── api/
│   │   └── taskboard.js                  # 看板接口
│   └── store/
│       └── taskboard.js                  # 看板状态
│
├── workspace/                            # 工作台模块
│   └── component/
│       ├── QuickActions.vue              # 快捷操作
│       ├── ReportCard.vue                # 报告卡片
│       └── ReportDrawer.vue              # 报告抽屉
│
└── setting/                              # 设置模块
    └── component/                        # 设置相关组件，后续可补充
```

说明：

- 模块内组件、接口、状态尽量放一起
- 一个模块的代码尽量不要散落在全局各处
- 后面加新业务时，优先先考虑是否应新增模块

---

### 4.4 `component/`

放全局通用组件，也就是多个模块都会复用的组件。

```text
component/
├── layout/
│   ├── WorkspaceLayout.vue               # 工作区布局
│   ├── AppHeader.vue                     # 顶部栏
│   ├── AppSidebar.vue                    # 侧边栏
│   ├── SidebarItem.vue                   # 侧边栏菜单项
│   └── TaskPane.vue                      # 任务面板
├── common/
│   ├── SuggestCard.vue                   # 建议卡片
│   └── NavBar.vue                        # 导航组件
└── index.js                              # 公共组件统一导出，后续需要时再补
```

说明：

- 只有“多个模块都会复用”的组件，才放这里
- 如果某个组件只属于一个模块，就放回对应 `module/*/component`

---

### 4.5 `store/`

放全局共享状态。

```text
store/
└── index.js                              # 全局 store 出口，后续需要时补
```

说明：

- 跨模块共享状态放这里
- 模块内专属状态优先放到 `module/*/store`

---

### 4.6 `api/`

放全局请求基础封装。

```text
api/
├── request.js                            # 请求实例和统一拦截器配置
└── mock.js                               # mock 数据或开发期模拟接口
```

说明：

- `api` 只做请求基础层
- 具体业务接口文件尽量放到对应模块的 `api/` 目录里

---

### 4.7 `utils/`

放通用工具函数。

```text
utils/
├── localStorage.js                       # 本地存储工具
├── local-state.js                        # 本地状态辅助工具
├── systemPrompt.js                       # 系统提示词工具
└── timeFormat.js                         # 时间格式化工具
```

说明：

- 工具函数要保持纯和轻
- 不要把业务逻辑塞进 `utils`

---

### 4.8 `style/`

放全局样式和样式变量。

```text
style/
├── style.css                             # 全局基础样式
├── main.css                              # 主样式入口
└── variables.css                         # 样式变量
```

说明：

- 样式目录统一后，后面更容易维护
- 避免样式文件散落在 `assets`、`styles`、根目录多个地方

---

### 4.9 `assets/`

放静态资源。

```text
assets/
└── vue.svg                               # 静态资源示例
```

说明：

- 图片、图标、静态文件统一放这里

---

## 5. 当前目录映射建议

### 5.1 当前 `views`

统一改成 `pages`

映射建议：

- `views/WorkspaceView.vue` -> `pages/WorkspacePage.vue`
- `views/TaskBoardView.vue` -> `pages/TaskBoardPage.vue`
- `views/TaskDetail.vue` -> `pages/TaskDetailPage.vue`
- `views/KnowledgeBaseView.vue` -> `pages/KnowledgePage.vue`
- `views/SettingsView.vue` -> `pages/SettingsPage.vue`
- `views/HelpCenter.vue` -> `pages/HelpPage.vue`
- `views/AuditLog.vue` -> `pages/AuditLogPage.vue`

### 5.2 当前 `feature`

统一改成 `module`

这样更接近“按业务模块组织”的直觉。

### 5.3 当前 `components`

拆成两类：

1. 真正全局复用的，迁到 `component`
2. 只属于某个业务模块的，迁到对应 `module/*/component`

映射建议：

- `components/chat/*` -> `module/agent/component/chat/*`
- `components/taskboard/*` -> `module/task_board/component/*`
- `components/workspace/*` -> `module/workspace/component/*`
- `components/layout/*` -> `component/layout/*`
- `components/common/*` -> `component/common/*`
- `components/AgentResultPanel.vue` -> `module/agent/component/AgentResultPanel.vue`
- `components/ExecutionLog.vue` -> `module/agent/component/ExecutionLog.vue`
- `components/MessageBubble.vue` -> `module/agent/component/MessageBubble.vue`
- `components/EvidencePanel.vue` -> `module/tender/component/EvidencePanel.vue`
- `components/TaskQuickView.vue` -> `module/tender/component/TaskQuickView.vue`

### 5.4 当前 `api`、`services`、`shared/api`

统一收敛成两层：

1. `api/`
   放请求基础封装
2. `module/*/api/`
   放业务模块自己的接口文件

映射建议：

- `api/request.js` 保留为全局请求基础层
- `api/drug-agent.js` -> `module/agent/api/agent.js`
- `api/taskboard.js` -> `module/task_board/api/taskboard.js`
- `shared/api/agent.js` 合并进 `module/agent/api/agent.js`
- `shared/api/tender.js` -> `module/tender/api/tender.js`
- `services/chatApi.js` 合并进 `module/agent/api/agent.js`
- `services/mock.js` -> `api/mock.js`
- `services/gemini.js` 如果仍保留前端直连模型能力，迁到 `module/agent/api/gemini.js`

### 5.5 当前 `stores`

拆成两类：

1. 跨模块共享状态 -> `store/`
2. 模块内状态 -> `module/*/store/`

映射建议：

- `stores/chatStore.js` -> `module/agent/store/chatStore.js`
- `stores/session.js` -> `module/agent/store/session.js`
- `stores/task.js` -> `module/tender/store/task.js`
- `stores/taskboard.js` -> `module/task_board/store/taskboard.js`

### 5.6 当前 `styles`、`style.css`、`assets/main.css`

统一收敛到 `style/`

映射建议：

- `style.css` -> `style/style.css`
- `assets/main.css` -> `style/main.css`
- `styles/variables.css` -> `style/variables.css`

### 5.7 当前 `shared`、`utils`

优先合并。

如果 `shared` 里只是工具或通用组件，建议分别并入：

- `component/`
- `utils/`
- `module/*/api/`

不要继续保留一个语义很宽的前端 `shared/` 目录。

---

## 6. 当前不建议继续保留的复杂目录

下面这些前端表达方式建议逐步删掉或并掉：

- `feature`
- `shared/api`
- `shared/component`
- `shared/util`
- `services`
- `components` 与 `component` 并存
- `views` 与 `pages` 并存

原则是：

**前端只保留一套表达方式，不要同一种东西出现两套目录。**

---

## 7. 分阶段改造计划

### Phase 1：先定标准

统一以后新增代码只进入：

- `app`
- `pages`
- `module`
- `component`
- `store`
- `api`
- `utils`
- `style`

### Phase 2：先迁页面和路由

优先处理：

- `views` -> `pages`
- `router` -> `app/router`
- `App.vue`、`main.js` -> `app`

这样页面入口先统一。

### Phase 3：再迁模块代码

按业务模块迁移：

1. `agent`
2. `tender`
3. `task_board`
4. `workspace`
5. `setting`

优先做到“模块内的组件、接口、store 放在一起”。

### Phase 4：最后清理公共目录

最后再整理：

- 全局 `component`
- 全局 `api`
- `utils`
- `style`

并删除旧的：

- `feature`
- `services`
- `shared`
- `views`

---

## 8. 删除原则

这次前端改造同样优先做减法。

优先删除：

1. 空目录
2. 重复 API 封装
3. 语义重复的组件目录
4. 已经没有引用的工具文件
5. 只做一层转发、没有实际价值的封装

如果一个文件只是：

- 简单转发另一个函数
- 不做逻辑处理
- 不做状态管理
- 不做参数转换

那大概率可以合并。

---

## 9. 最终结论

前端改造完成后，目录表达应该稳定成一句话：

**`app` 管启动和路由，`pages` 管页面，`module` 管业务模块，`component` 管公共组件，`api` 管请求基础，`store` 管共享状态，`utils` 管工具，`style` 管样式。**

这样前后端会统一很多：

- 后端按 `scene` 收业务
- 前端按 `module` 收业务

整体项目会比现在清楚很多。
