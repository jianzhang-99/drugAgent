# 医药监管AI系统工具描述优化

## 一、概述

本文档定义了医药监管AI系统的核心工具描述（Tool Description），采用 OpenAI Function Calling 格式进行描述。工具描述用于指导 AI 模型理解何时以及如何调用各类工具，是实现精准工具调用的基础。

---

## 二、核心工具定义

### 2.1 标书审查工具 (review_tender)

**使用场景**：当用户需要审查标书文件、识别围标串标风险、分析技术方案雷同、比对商务条款等场景时调用。

```json
{
  "name": "review_tender",
  "description": "对多份投标文件进行深度比对审查，识别围标串标风险、技术方案抄袭、报价异常等违规行为。适用于招投标合规性审查场景。\n\n【触发条件】当用户提及以下意图时调用：\n- 上传/提交/审查标书文件\n- 检测围标、串标、陪标行为\n- 比对多家投标方技术方案相似度\n- 分析报价合理性\n- 生成投标合规性报告\n\n【核心能力】\n1. 多文档交叉比对：支持对2-N份标书同时进行文本结构、技术方案、报价条款的相似度分析\n2. 风险识别：自动识别高风险行为（如核心团队重叠、方案高度雷同、报价梯度异常）\n3. 证据链生成：提供具体证据段落和相似度百分比\n4. 结构化报告：输出可导出的审查报告\n\n【限制】\n- 至少需要2份标书文件才能执行比对\n- 单次审查最多支持20份文件\n- 支持格式：docx, doc, pdf, txt, md",
  "parameters": {
    "type": "object",
    "properties": {
      "sessionId": {
        "type": "string",
        "description": "会话唯一标识ID，用于关联上下文和历史记录"
      },
      "fileIds": {
        "type": "array",
        "items": {"type": "string"},
        "description": "待审查文件的唯一标识列表，至少需要2个文件ID",
        "minItems": 2,
        "maxItems": 20
      },
      "reviewFocus": {
        "type": "string",
        "enum": ["围标风险", "技术方案雷同", "商务条款", "全面审查"],
        "description": "审查重点方向，不指定时默认为全面审查",
        "default": "全面审查"

      "userInstruction": {
        "type": "string",
        "description": "用户的额外补充说明或特定要求，如重点关注的条款、特殊行业规范等"
      },
      "needStructuredReport": {
        "type": "boolean",
        "description": "是否需要返回完整的结构化报告JSON（含风险等级、证据列表、详细建议）",
        "default": true
      }
    },
    "required": ["fileIds"]
  }
}
```

### 2.2 知识库检索工具 (knowledge_retrieve)

## 四、错误处理与降级策略

### 4.1 错误分类与处理

| 错误类型 | 错误码 | 处理策略 | 用户可见信息 |
|---------|--------|---------|-------------|
| 参数缺失 | PARAM_MISSING | 返回具体缺失参数提示，引导用户补充 | "请提供待审查的文件ID列表" |
| 参数格式错误 | PARAM_INVALID | 提示正确格式要求 | "fileIds应为数组格式，如 ['file1', 'file2']" |
| 文件数量不足 | FILE_COUNT_INSUFFICIENT | 标书审查至少2份，知识检索无此限制 | "至少需要2份标书文件才能进行比对审查" |
| 文件不存在 | FILE_NOT_FOUND | 尝试从会话历史恢复，或提示上传 | "未找到文件file_001，请确认是否已上传" |
| 文件格式不支持 | FILE_FORMAT_UNSUPPORTED | 提示支持格式列表 | "暂不支持wps格式，请上传docx/doc/pdf/txt/md格式" |
| 知识库无命中 | KNOWLEDGE_NO_HIT | 降级为通用对话或人工转接 | "知识库中未找到相关内容，建议补充资料或咨询专业人士" |
| 置信度不足 | LOW_CONFIDENCE | 返回部分结果+人工复核建议 | "检索置信度较低，建议结合业务实际情况判断" |
| 服务内部错误 | INTERNAL_ERROR | 记录日志，降级为通用对话 | "服务繁忙，请稍后重试" |

### 4.2 降级策略

#### 降级链路图

```
标书审查 (review_tender)
    │
    ├─► 正常流程：返回完整审查报告 + 证据链
    │
    ├─► 降级A（文件不足）：返回警告 + 单文件基础分析
    │
    ├─► 降级B（部分文件读取失败）：返回成功报告（仅包含可读文件）
    │
    └─► 降级C（完全失败）：返回友好错误 + 通用合规建议

知识检索 (knowledge_retrieve)
    │
    ├─► 正常流程：返回高置信度答案 + 引用
    │
    ├─► 降级A（低置信度）：返回答案 + 低置信度警告 + 建议人工确认
    │
    ├─► 降级B（无命中）：返回知识库补充建议 + 引导人工咨询
    │
    └─► 降级C（服务异常）：降级为通用对话能力

合同预审 (review_contract)
    │
    ├─► 正常流程：返回风险条款列表 + 修改建议
    │
    ├─► 降级A（文本碎片化）：返回部分分析 + 补充材料建议
    │
    └─► 降级B（服务异常）：返回友好错误 + 基本合规检查清单

风险预警 (risk_alert)
    │
    ├─► 正常流程：返回风险评级 + 预警详情 + 缓解建议
    │
    ├─► 降级A（数据不足）：返回有限分析 + 数据补充建议
    │
    └─► 降级B（服务异常）：返回友好错误 + 通用风险提示
```

#### 降级响应示例

### 4.3 错误处理的系统提示词

在调用工具时，系统应注入以下错误处理指导：

```
【错误处理指导】
当工具返回错误时，按照以下优先级处理：
1. 如果是用户输入错误（参数缺失/格式错误），引导用户修正输入
2. 如果是部分成功（部分文件可读），返回可用结果并明确告知哪些失败了
3. 如果是完全失败，输出友好错误信息并提供替代方案
4. 任何情况下都不要向用户暴露内部错误堆栈或技术细节
5. 错误信息应使用自然语言，避免出现错误码或技术术语
```

## 五、工具选择决策树

### 5.1 工具选择逻辑

```
用户输入
    │
    ├─► 包含文件上传/标书/投标/围标/串标/雷同？
    │       │
    │       └─► YES ──► review_tender (标书审查)
    │
    ├─► 询问法规/政策/标准/合规要求？
    │       │
    │       └─► YES ──► knowledge_retrieve (知识检索)
    │
    ├─► 提交合同文本/条款审查/合同风险？
    │       │
    │       └─► YES ──► review_contract (合同预审)
    │
    ├─► 药品/器械风险预警/合规分析/异常检测？
    │       │
    │       └─► YES ──► risk_alert (风险预警)
    │
    └─► 通用问答/闲聊/其他
            │
            └─► 直接对话（不调用工具）
```

### 5.2 意图歧义处理

当用户意图不明确时，优先采用保守策略：

1. **标书+法规混合**：优先调用 `review_tender`，因为标书审查结果可附带法规对照
2. **合同+风险混合**：优先调用 `review_contract`，合同审查会覆盖基础风险识别
3. **知识+预警混合**：优先调用 `knowledge_retrieve`，返回的知识可作为预警参考

如仍无法判断，返回澄清问题而非强行调用工具。

## 六、附录

### 6.1 风险等级定义

| 等级 | 取值 | 含义 | 建议操作 |
|------|------|------|---------|
| 高风险 | HIGH | 明确违规或高度可疑 | 建议上报/深入调查 |
| 中风险 | MEDIUM | 存在疑问需进一步核实 | 建议补充材料后复核 |
| 低风险 | LOW | 基本合规，轻微瑕疵 | 可忽略或仅作记录 |
| 无风险 | NONE | 完全合规 | 通过 |
| 待定 | PENDING | 信息不足无法判断 | 补充信息后重评 |

### 6.2 支持的文件格式

| 工具 | 支持格式 | 说明 |
|------|---------|------|
| review_tender | docx, doc, pdf, txt, md | 标书文件 |
| review_contract | docx, doc, pdf, txt | 合同文件 |
| knowledge_retrieve | 无文件上传 | 仅支持文本检索 |
