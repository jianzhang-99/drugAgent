# Day 1：收敛后端主链路

## 目标
把 Agent 层收敛成最小可运行链路，保证“普通 chat 请求能正确进入场景执行”。

## 必做事项

### 1. 收敛 Agent 层
只保留并聚焦这 4 个 service：

- `AgentChatService`
- `AgentSessionService`
- `AgentSceneService`
- `AgentResponseService`

要求：
- 新旧 route / dispatcher 逻辑不要再混着扩
- `AgentChatService.chat()` 要正式跑起来
- `AgentSceneService` 负责判断场景并执行
- `AgentResponseService` 统一返回 `AgentChatResp`

### 2. 修正会话表和实体
完成这些对齐：

- 刷新 `chat_session`
- 刷新 `chat_message`
- 实体类和表一致
- 去掉旧 `scene` 语义
- 用 `lastScene` 和 `summary`

### 3. 完成 `AgentSessionService` 的最小能力
至少完成：

- `getOrCreateSession`
- `loadSessionContext`
- `saveUserMessage`
- `saveAssistantMessage`
- `updateSessionTitleIfNeeded`

### 4. 让 chat 主流程真正可跑
主流程要固定成：

- 读取 session
- 构建上下文
- 调 `AgentSceneService`
- 回写消息
- 返回响应

## Day 1 验收标准
你能做到：

- 调 `/agent/chat`
- 后端不会乱跳
- 能返回一个结构完整的 `AgentChatResp`
- 数据库里能看到 session 和 message 被写入

# Day 2：打通标书审查闭环

## 目标
让 `TENDER_REVIEW` 成为第一个真正可跑通的场景。

## 必做事项

### 1. `AgentSceneService` 只先支持两个场景
- `TENDER_REVIEW`
- `UNKNOWN`

其他场景直接返回“暂未实现”，不要展开。

### 2. 打通标书审查执行链
你要确认这一条链能完整工作：

`AgentChatService`
-> `AgentSceneService`
-> `TenderReviewOrchestratorService` 或你当前实际的标书编排器
-> `ReviewTenderToolService`
-> `TenderReviewWorkflow`

重点是：
- 不要让 `AgentChatService` 直接碰 workflow
- 标书场景统一走 orchestrator 主入口

### 3. 文件上传 / 标书数据准备可用
如果当前前端还没接文件上传完整链路，就先保证后端最小输入能跑。
可以先允许：
- 通过 fileIds
- 或通过已有 mock / test case
- 或通过固定测试文件

目标不是上传体验完美，而是**标书场景能执行起来**。

### 4. 返回结构要稳定
必须保证最后前端拿到的至少有：

- `scene`
- `summary`
- `answer`
- `report`
- `evidenceList`

## Day 2 验收标准
你能做到：

- 输入“帮我看看这两份标书是否有围标风险”
- 后端识别 `TENDER_REVIEW`
- 执行标书链路
- 返回结果而不是空响应

# Day 3：前端联调 + 异常兜底 + 最小展示

## 目标
把第一条场景真正变成“能演示”的 MVP。

## 必做事项

### 1. 前端接通最小链路
前端先做最小页面，不求完美：

- 聊天输入框
- 会话区域
- 上传文件入口
- 返回结果展示区

### 2. 结果展示优先级
前端优先展示：

1. `answer`
2. `summary`
3. `riskLevel`
4. `report`
5. `evidenceList`

不要一开始做太多视觉花活。

### 3. 做基本异常兜底
至少要处理：

- 没上传足够文件
- 标书数据缺失
- workflow 报错
- 返回空结果
- 接口超时 / 失败

前端要能给出最基本提示，不要直接白屏。

### 4. 给自己留调试时间
Day 3 一定要留至少半天做：
- 接口调试
- 返回格式修正
- 前端字段映射修正
- 数据结构对齐

## Day 3 验收标准
你能做到：

- 从前端发起一次标书审查
- 后端返回结果
- 前端能稳定展示
- 出错时至少有提示，不崩
